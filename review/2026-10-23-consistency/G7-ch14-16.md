### M1 major — The glossary says the extrusion multiplier is "never set from caliper readings", but the Core One+ gates that link to that entry set it from caliper readings
- `docs/manual/16-glossary.md:109`: "set by eye on the centre of a top surface, **never from caliper readings**. **Not** a size lever"
- `docs/manual/print/00-slicer-setup.md:246` (Gate A row, which links `../16-glossary.md#e`): "Still over → reduce [extrusion multiplier](../16-glossary.md#e) in 1 % steps"
- Ch 15 repeats the Core One+ procedure:
  - `15-troubleshooting.md:37` and `:506`: "bring the extrusion multiplier down in 1 % steps"
  - `:50` and `:512` (Gate B): "Tight means extrusion multiplier down 1 % and reprint"
- **Evidence:** a builder who follows the Gate A link lands on a definition that forbids the action Gate A has just told them to take. The glossary rule is Ellis' Voron-side rule (Ch 14 Read first, 14.11), but it is stated globally.
- **Fix (glossary row text):** "The slicer's scaling of how much plastic is extruded. On the Voron (Ch 14) it is set by eye on the centre of a top surface, never from caliper readings, and Voron parts need no other compensation (Ellis). On the Core One+, Gates A and B are the one exception: a cube or bearing seat still over size after 0 % shrinkage / 0 XY compensation takes the multiplier down in 1 % steps. Never negative XY size compensation."

- **Fix:** add one sentence to 14.18 Do 3. "Save the ASA filament preset as `Prusament ASA - Voron 2.4` with the `Voron 2.4 350` printer selected; in its Custom G-code replace the `M572 …` line with `SET_PRESSURE_ADVANCE ADVANCE=<your value>` and delete `M142 S40`." In 14.35 step 2, say: "Save `Prusament PLA @COREONE HF0.4` and `Prusament PETG @COREONE HF0.4` the same way as `… - Voron 2.4`, delete their `M572`/`M142` lines, then set Nominal / Minimal: PLA 35 / 0, PETG 40 / 0."

### M4 minor — Step 13.41 says the Prusa chamber values emit `M141`/`M191`; Step 14.35 (correctly) says nothing is emitted
- `13-initial-startup.md:1187`: "the Prusa filament profile's chamber values emit `M141`/`M191`, which this config does not define (Klipper answers `Unknown command`, harmless)"
- `14-calibration.md:1487`: "neither has `M141` or `M191`". Its own source note `:1495` says "chamber commands only with automatic temperature commands on".
- **Evidence:** PrusaSlicer 2.9.6 `GCode.cpp` `_print_first_layer_chamber_temperature` writes the command only `if (autoemit && ! temp_set_by_gcode)`. 13.41 Do 1 unticks automatic temperatures, so no `M141`/`M191` is ever written. The vendor presets' start-filament G-code has none either.
- **Fix (13.41 sentence):** "Chamber temperature is **not** a slicer setting on this machine yet: with automatic temperature commands off, PrusaSlicer writes no `M141`/`M191`; the chamber is `CHAMBER=` on `PRINT_START`, kept at **0** …"
